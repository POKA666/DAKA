# 小打卡 · 每日计划

纯本地、不联网、免安装的手机端打卡网页。UI 沿用小账本：同一套纸色底色、绿色主色、卡片与底部弹层。

## 能做什么

- **计划随便加**：名字、图标、颜色、每天或每周几，最多 30 个。
- **点一下圆圈就打卡**，完成态是实心勾；点「⋯」改名字/图标/颜色/频率，或删除（历史会保留）。
- **每天 23:00 结算**（可在设置里改）：到点后当天不能再打卡；过去的日子不能补打；第二天的计划表在次日首次打开时自动生成。改结算时间也不会解锁已经结算的今天，新时间从第二天生效。
- **今日页**：完成率大数字、连续天数、今日/本周进度、当天备忘录（自动保存）。
- **日历页**：月热力图（按当天完成率深浅）、点某天查看那天的计划和备忘录、当月完成率/全勤/打卡次数。
- **分析页**：总览（累计/全勤/当前与最长连续/记录天数/整体完成率）、近 7 天与近 30 天可切换；完成率趋势折线图（没有计划的日子折线断开，不按 0% 算）、与上一个同期的涨跌、一句文字总结、「完成得好 / 需要加强」排行、一周里哪天最容易漏的柱状图、每日/每周/每月明细。
- **设置页**：6 个主题色 + 自定义取色、上传手机照片当壁纸（自动压缩后存在本机）、字体大中小、结算时间、导出/导入 JSON 备份、清空记录、恢复默认。
- **离线可用**：首次打开后断网也能用；「添加到主屏幕」后像 App 一样全屏打开。

## 文件

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面骨架（品牌区、四个标签页、弹层） |
| `styles.css` | 样式，沿用小账本的设计令牌 |
| `store.js` | 数据层与规则（localStorage 键 `xiaodaka.v1`），可在 Node 里单独测试 |
| `app.js` | 四个页面的渲染与交互 |
| `sw.js` | 离线缓存（网络优先，断网回缓存） |
| `manifest.json` | 添加到主屏幕时的名称、颜色、图标 |
| `icons/` | 图标（含 192/512/maskable/apple-touch） |
| `tools/` | 只在电脑上做维护用：图标生成、演示数据、逻辑测试；**发布时不用上传** |

## 发布（不用装任何软件）

1. 在 GitHub 新建一个仓库，选 **Public**，例如叫 `daka`。
2. 打开仓库页面 → **Add file → Upload files**，把 `index.html`、`styles.css`、`store.js`、`app.js`、`sw.js`、`manifest.json` 和整个 `icons` 文件夹拖进去 → **Commit changes**。（`tools/`、`README.md` 可以不上传。）
3. 仓库 **Settings → Pages** → Source 选 **Deploy from a branch** → 分支 **main**、目录 **/ (root)** → **Save**。
4. 等 1 分钟左右，打开 `https://你的用户名.github.io/daka/`。
5. 手机用 Safari / Chrome 打开这个网址 → 分享菜单 →「添加到主屏幕」。

以后更新：同样用 Upload files 覆盖同名文件并提交，等 1 分钟，手机上关掉页面再打开即可。

## 数据与备份（很重要）

- 打卡数据只存在**这台设备的这个浏览器**里，不联网、不上传，所以换手机、换浏览器、清理浏览器数据都会看不到旧记录。
- 在「设置 → 数据 → 导出备份」会下载一个 JSON 文件；换设备后「导入备份」即可恢复。
- 不要换发布地址（比如改仓库名）：网址变了，浏览器会当成另一个网站，旧数据就“看不见”了。真要大改，先导出备份。

```bash
node tools/test-store.js     # 数据层逻辑测试（85 条断言，全部通过才改代码）

```
